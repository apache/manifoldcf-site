Security

Security Policy & Trust Boundaries

How to responsibly disclose security vulnerabilities to the Apache Security Team and how to harden Apache ManifoldCF deployments in production.

Reporting a Vulnerability

If you discover a potential security issue in Apache ManifoldCF, please report it privately to the Apache Security Team at security@apache.org.

Please do not report security issues via public GitHub issues, Jira tickets, pull requests, or public mailing lists. See the ASF Security Team vulnerability handling process for full details.

Trust Boundaries

Architecture Security Model

Document ACL Security Model (Wiki)

1. Administrative Consoles (/mcf-crawler-ui & /ui/)

Authenticated operational consoles for connections, authorities, mappers, jobs, and reports. State-changing actions require HTTP POST and per-session CSRF request tokens; session cookies enforce HttpOnly, SameSite=Lax, and a 30-minute timeout.

Operator action: Replace default admin/admin credentials in properties.xml and terminate TLS (HTTPS) in front of the console.

2. REST API Services (/mcf-api-service & /api/v2/*)

Programmatic administrative APIs requiring authentication on all operational endpoints (HTTP Basic Auth or v1 session login; empty credentials rejected). Obfuscated secrets are masked in API responses and GitOps exports.

Operator action: Configure dedicated API credentials and restrict network access to trusted automation clients. Only container health probes remain open.

3. Authority Service (/mcf-authority-service / /UserACLs)

Internal backchannel queried by search-engine authorization plugins (Solr, OpenSearch, Elasticsearch). User identifiers are treated as untrusted input—including RFC 4515 LDAP filter escaping.

Operator action: Isolate /UserACLs on a private search-engine network or place behind authenticating reverse proxy / container auth.

4. Connectors & Credential Obfuscation

Connectors harden XML parsers against external entity resolution (XXE) and DTD processing and escape backend queries. Connector secrets support reversible obfuscation backed by deployment-specific key material.

Operator action: Set org.apache.manifoldcf.obfuscation.passcode and org.apache.manifoldcf.obfuscation.salt (or MCF_OBFUSCATION_* env vars) and restrict access to properties.xml and the database.

Production Hardening Checklist

  • Replace default admin / admin credentials in properties.xml for UI and API logins.
  • Configure deployment-specific obfuscation passcode and salt via properties or environment variables.
  • Terminate TLS (HTTPS) in front of administrative consoles and REST APIs.
  • Network-isolate /mcf-authority-service (/UserACLs) so only trusted search nodes can query it.
  • Keep OpenJDK 25 and Apache ManifoldCF updated to the latest 2.x release (2.31) and verify release PGP signatures.

Supported Versions

Security fixes are applied to the active development branch (trunk) and released on the latest 2.x release line. Users are strongly encouraged to stay on Release 2.31 or newer.
